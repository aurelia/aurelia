# AUR3179: Route ID Shadows Another Route's Public Path

## Warning Message

`AUR3179: Route ID "%s" on %s shadows a public path of %s. URL entry retains ID-first lookup. Give these routes distinct public paths or IDs so generated links can identify each route after reload.`

## Description

This development warning identifies a route ID that matches another route's literal path in the same routing context. Incoming URLs retain the router's existing ID-first interpretation. As a result, a link generated for the route with that path can open a different component after a reload or in a new tab.

For example, these routes give `reports` two meanings:

```typescript
routes: [
  { id: 'reports', path: 'archive', component: Archive },
  { id: 'report-list', path: 'reports', component: Reports },
]
```

The `/reports` address identifies `Archive` through its ID. It cannot also be an unambiguous public address for `Reports`.

## Solutions

Give `Reports` a distinct public path, such as `report-list`, and update links intended to reach it. This preserves existing `/reports` links to `Archive`.

Alternatively, rename the shadowing ID if your application can migrate callers and published URLs that use it. Check bookmarks and links from other systems as well as in-app navigation: changing an ID can change the meaning of an existing URL.

The warning does not reject the configuration or change navigation precedence. Test both a generated link and a direct visit to its URL when resolving the collision.
