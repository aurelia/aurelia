# AUR3273: Invalid Application URL Reference

## Error Message

`AUR3273: Expected an application URL reference, got %s. Use a path such as /users or ../reports. Document and external URLs belong in native links.`

## Description

`router.navigate()`, `router.createHref()` and the `url` attribute accept application URL references. Examples include `/reports`, `../reports`, `?page=2` and `#details`.

This error occurs when the value is not a string or cannot be used as an application reference. Absolute document URLs such as `https://example.com/reports` and protocol-relative URLs such as `//example.com/reports` are rejected, including URLs on the application's own origin.

## Solutions

For an application destination, pass its application path. If the app is deployed under `/app/`, navigate to `/reports`, rather than `/app/reports` or the full browser URL.

```typescript
await router.navigate('/reports?period=month');
```

`createHref()` returns a browser-facing link. Do not pass its output back into `navigate()`; keep the application reference for navigation and use the generated href in a native link.

Invalid input can throw synchronously, before a navigation is queued. Wrap the call itself when handling errors:

```typescript
try {
  const completed = await router.navigate(reference);
  if (!completed) {
    // A navigation guard canceled the transition.
  }
} catch (error) {
  // Handles invalid input and errors raised during navigation.
  console.error(error);
}
```

Input validation failures do not emit `au:router:navigation-error`, because no transition has started. A guard cancellation returns `false`; it is not a signal to fall back to document navigation.

For another document or site, use a native anchor. Mark document-relative links `external` when the router's `href` attribute is registered:

```html
<a href="/downloads/report.pdf" external>Download report</a>
<a href="https://example.com/help">Help</a>
```

Use `location.assign()` or `location.replace()` for programmatic document navigation. If a shared menu supplies both route references and document URLs, keep that distinction in the menu data so the renderer can select the appropriate link.

See [application URL navigation](../../../router/application-url-navigation.md) for reference-resolution rules.
